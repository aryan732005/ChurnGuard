API reference

REST endpoints for churn prediction and analytics. Base URL: /api

Architecture

flowchart TB
  ingest[Data ingestion CSV/CRM] --> prep[Preprocess & feature engineering]
  prep --> train[train_model.py + MLflow]
  train --> artifacts[(models/ stats.json)]
  artifacts --> api[FastAPI API]
  api --> ui[Jinja2 frontend]
  api --> batch[Batch & drift PSI]

See docs/design-decisions.md and docs/data-privacy.md in the repo.

POST /api/predict

Score a single customer profile.

Request

{
  "tenure": 12,
  "Contract": "Month-to-month",
  "MonthlyCharges": 70.0,
  "TotalCharges": 840.0,
  "InternetService": "Fiber optic",
  "PaymentMethod": "Electronic check",
  "gender": "Male",
  "SeniorCitizen": 0,
  "Partner": "No",
  "Dependents": "No",
  "PhoneService": "Yes",
  "MultipleLines": "No",
  "OnlineSecurity": "No",
  "PaperlessBilling": "Yes"
}

Response

{
  "churn_probability": 67.42,
  "prediction": "Churn",
  "confidence": 34.8,
  "risk_level": "High",
  "top_factors": [
    { "feature": "Contract_Month-to-month", "impact": 0.82 }
  ]
}

Deployment & model versioning

ChurnGuard is designed to run beyond localhost — via Docker, uvicorn/gunicorn behind a reverse proxy, or your cloud VM.

Required environment variables

ADMIN_USER=admin
ADMIN_PASSWORD=<strong-secret>
CLERK_PUBLISHABLE_KEY=pk_...   # optional — UI auth
CLERK_SECRET_KEY=sk_...        # server only, never expose to browser
OPENAI_API_KEY=sk-...          # optional — NL explanations
CORS_ORIGINS=https://your-domain.com

Model artifacts

Training (python train_model.py) writes to models/, data/stats.json, and mlruns/. The API loads artifacts at process startup.

Promotion: After retraining, restart the app (or redeploy the container) to serve the new model. Version history is tracked in data/model_versions.json; there is no automatic hot-swap without a restart.

Admin-only routes: /retrain, /logs, POST /api/retrain-simulation.

Executive report

Download or email the PDF executive summary.

GET /api/executive-summary.pdf
POST /api/report/send
{ "email": "stakeholder@company.com" }

Configure SMTP in .env.local to send live email (SMTP_HOST, SMTP_USER, SMTP_PASSWORD). Without SMTP, reports are queued under data/pending_report_emails/.

Query param: threshold (0.05–0.95). Returns precision/recall curve.
